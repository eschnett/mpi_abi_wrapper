# Expected failures of MPICH's C test suite over this project, wrapping the
# Open MPI 4.1.6 that Ubuntu 24.04 ships (STAGES.md S7). One line per test,
# `<dir>/<program> <np> : why`, in runtests' own naming.
#
# This row runs on Linux, in the container ci-scripts/suite/linux-suite.sh
# starts, because no Open MPI 5.0.x launcher works on macOS 26 with or
# without this project (test/README.md). 1231 tests, and the failures below.
#
# **The list is version-specific and most of it is not about this project.**
# Open MPI 4.1.6 provides 466 of the ABI's 688 entry points, so everything
# MPI-4.0 added -- sessions, partitioned communication, persistent
# collectives, the large-count `_c` forms, MPI_Isendrecv, MPI_Info_get_string
# -- is a stub answering MPI_ERR_UNSUPPORTED_OPERATION, which is what
# decision 6 requires and what an application over this wrapper will see. A
# newer Open MPI moves those lines, which is why the variant is what selects
# the file.
#
# **Triage here is partial, and the lines say which is which.** The first
# three groups are attributed mechanically -- from the probe header that
# records what this implementation has, and from the compiler's own message.
# The fourth is shared with the MPICH row, so its cause is already known. The
# last two are honest placeholders: what was observed, and nothing claimed
# beyond it. Finishing them is the first task of whoever picks this up, and
# ci-scripts/suite/run-suite.sh --gate-only re-runs the comparison against a
# TAP file already in hand.
#
# **The rma/linked_list family is load-sensitive here, and the gate is what
# established that.** Three runs of this row on the same host: under load all
# four of rma/linked_list and rma/linked_list_bench_lock_{excl,shr,shr_nocheck}
# failed with an RMA error from Open MPI itself; on a quiet run three of them
# passed and the gate reported them as "expected failure that passed", which
# is exactly the signal that mechanism exists for. Only the one that failed
# in the confirming run is listed. If a loaded run puts the other three back,
# they are that machine's, not this project's -- the same test under Open
# MPI's own mpicc is the check.

# --- the same causes as the MPICH row ------------------------------------
#
# Each of these fails over MPICH too and for a reason established there;
# ci-scripts/suite/xfail-mpich.txt is where the reasoning lives.

attr/fkeyvaltype 1 : 32 keyvals per iteration over 1024 datatype-pool objects is 32,768 in one process, against a 1024-slot table. MPIWRAPPER_KEYVAL_SLOTS is fixed and its entries are never reclaimed, because MPI-5.0 7.7 keeps a freed keyval usable by attributes not yet deleted, so no point is known-dead (NOTES.md #6.2). MPICH itself recycles the integer and has no such ceiling.
errhan/commcall 2 : 2000 MPI_Comm_create_errhandler calls against MPIWRAPPER_ERRHANDLER_SLOTS, which is 256 and is never reclaimed -- an errhandler is deallocated only after every object it was set on (MPI-5.0 9.4), which the wrapper cannot observe. Measured: 3490 of the test's 4000 handler invocations never reach the application's function.
errors/coll/noalias2 4 : four of the test's aliasing checks -- the rooted ones, MPI_Gather, MPI_Gatherv, MPI_Scatter and MPI_Scatterv with sendbuf == recvbuf -- return MPI_SUCCESS through the wrapper where MPICH answers MPI_ERR_BUFFER, while the six unrooted checks in the same test do fire. The same binary built with MPICH's own mpicc passes. Nothing in the wrapper touches either buffer pointer, so what differs is not yet known; the next step is to compare what MPICH's error-checking layer is handed in the two cases.
errors/coll/noalias3 4 : the same four checks, in the large-count (_c) forms.
errors/coll/reduce_local 1 : MPI_IN_PLACE passed to MPI_Reduce_local, where MPI-5.0 6.9.7 forbids it. NOTES.md #5.3 translates a sentinel only where it is legal for that parameter, so here the ABI's MPI_IN_PLACE reaches MPICH as an ordinary address and is dereferenced. Same shape as the nullargs above.

init/version 1 : MPI_Get_version forwards the implementation's answer (MPICH 4.3.1 says 4.1) while the ABI header is fixed at MPI-5.0, and the test compares the two. Forwarding is the honest half: an application told 5.0 would believe entry points work that this wrapper answers with MPI_ERR_UNSUPPORTED_OPERATION. The two can agree only over an implementation that is itself MPI-5.0.
io/i_setviewcur 4 : the same, through MPI_File_iset_view.
io/setviewcur 4 : MPI_DISPLACEMENT_CURRENT is (MPI_Offset)-1 in the ABI header and -54278278 in ROMIO, which is what both MPICH and Open MPI use for MPI-IO, so MPI_File_set_view is handed -1 and answers "Invalid displacement argument". A bug of ours, diagnosed in S7 and not fixed there: #5.3's sentinel rule is about *pointer* sentinels and this is the one that is an integer, in one parameter of one entry point.
rma/wincall 2 : the same table for windows: the test loops MPI_Win_create_errhandler and MPI_Win_set_errhandler 1000 times, and past 256 the wrapper has no slot, so MPI_ERRHANDLER_NULL reaches MPI_Win_set_errhandler.
