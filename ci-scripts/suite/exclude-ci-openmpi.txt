# Individual test *lines* not to run over Open MPI, with a reason each.
#
# This is not an expected-failure list and cannot be one. check-tap.py compares
# observed results against xfail-ci-openmpi*.txt, and both work because the test
# ran and produced a TAP line. A test that exhausts the host produces nothing:
# the runner is killed, the job uploads no artifact, and there is no line to
# expect. So the only way to keep such a test from costing the whole shard is to
# stop it being run, which is what this file does -- run-suite.sh drops matching
# lines from the generated testlists before runtests sees them.
#
# Format: one extended regular expression per line, matched against a testlist
# line with `grep -E`. A `#` line is a comment and a reason is required above
# every pattern, for the same reason the xfail lists require one.
#
# **Read this before adding a pattern: this file cannot make the rma shard safe
# over Open MPI 5.0.10, and two measured runs say so.** It was written when the
# only known casualty was getfence1. Since then:
#
#   * excluding getfence1 moved the death 26 minutes later, into
#     `putfence1 -count=16000000` at 8.09 + 6.79 GB (run 32291327971);
#   * and `rma/transpose7` -- which lives in the *main* rma testlist, carries no
#     mem= annotation and takes no count arguments at all -- reached
#     10.73 + 3.93 GB and killed a runner in the same run, after surviving the
#     previous one with 1.2 GB to spare.
#
# So the amplification is a property of the whole rma directory over 5.0.10 and
# not of the datatype-pool tests, nor of the annotated ones, and no list of
# test-line patterns converges. transpose7 in particular is marginal rather than
# fatal, which is why this shard is flaky as well as failing.
#
# The two patterns below are kept because they are measured and because they buy
# the shard 26 minutes, not because they fix it. The real choices are upstream or
# at configure time -- see ci-scripts/suite/README.md, and the probe's `ofi` case,
# which tests whether libfabric gives these windows an accelerated BTL and makes
# the whole question go away.

# Open MPI 5.0.10 spends about 14.6 GB across two ranks here, against the mem=3
# it declares and the ~2.7 GB Open MPI 4.1.8 spends on the same test with the same
# wrapper -- 5.4x, and 6.5x on the origin rank alone. Measured, run 32284464458.
^getfence1 .*-count=16000000

# The same shape at mem=2, and the same outcome: 8.09 + 6.79 GB, runner killed.
# Measured in run 32291327971, once the getfence1 lines above stopped being run.
^putfence1 .*-count=16000000
