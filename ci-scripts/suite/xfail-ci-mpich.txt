# Expected failures of MPICH's C test suite over this project in GitHub Actions,
# over **MPICH 5.0.1 built from source, on every architecture** -- x86_64,
# aarch64 and i386 alike. Anything true of one architecture only belongs in
# xfail-ci-mpich-<arch>.txt beside this file; check-tap.py reads the two as one
# and rejects a test listed in both.
#
# One line per test, `<dir>/<program> <np> : why`, in runtests' own naming.
# check-tap.py enforces it in both directions -- an unlisted failure fails the
# run, and so does a listed test that passed or that did not run -- and a line
# with no reason after the colon fails the run too. `--update-xfail` writes bare
# lines for a human to add reasons to; it can never make a red run green.
#
# **Written from run 32155423441**, the first run of this suite over 5.0.1 with
# one MPI job per test: 842 tests, 789 passed, 41 failed, 12 skipped by the suite.
#
# **Flaps go in flaky-ci-mpich.txt now, not in a paragraph here.** This file briefly
# carried `errors/comm/subcomm_abort 4` as prose, because a test that fails in one run
# and passes in the next cannot be expressed as an expected failure -- listing it fails
# the runs it passes, not listing it fails the runs it fails. check-tap.py's --flaky
# category exists for exactly that, so the test has a line of its own there and a red
# run no longer needs a human to read a comment to interpret.
# The count of lines here is `grep -cvE '^\s*(#|$)'`, the same lines check-tap.py
# reads; plain `wc -l` counts this header too.
#
# **37 of these 41 are the same tests, with the same causes, that
# xfail-mpich.txt records against MPICH 4.3.1 with the 4.3.1 suite** -- the
# reasons below are carried across and re-verified against this run's own output,
# not retyped from memory. What changed is worth stating, because both directions
# are informative:
#
#   * `init/version` is **gone**, and it is now gone from every list rather
#     than only this one. It failed because MPI_Get_version forwarded the
#     implementation's answer while the ABI header is fixed at MPI-5.0, and it
#     passed here first because MPICH 5.0.1 happens to declare MPI_VERSION 5.
#     Decision 24 makes it pass everywhere: MPI_Get_version now reports the
#     standard *this library* presents, which MPI-5.0 2.7 requires it to agree
#     with the macro about.
#
#     **The four lists were, between them, arguing the wrong side.** Each said
#     forwarding was "the honest half" and that the two could agree only over
#     an implementation that is itself MPI-5.0. This test is MPICH's own
#     assertion of the standard's requirement, and it was recorded here as an
#     expected failure with a rationale defending the behaviour it was
#     reporting. mpif's environment check said the same thing independently
#     (NOTES.md #10), and it took a consumer aborting to notice. An expected
#     failure whose reason argues against a conformance test is worth a second
#     look; that is the shape of this one.
#   * The three lines the old list groups as **(g) timing, in this environment**
#     are gone too, and that group was always about one laptop: all three passed
#     on GitHub's runners, which is what a per-environment list exists to record.
#   * Four lines are **new**, all of them group (c) and all of them the same
#     symbol: the 5.0.1 suite added tests that use MPI_Errhandler_set.
#
# The groups keep the old file's letters so the two lists share a vocabulary.
# Each is a *kind* of difference, and the kind matters more than the count:
#
#   (b) a fixed-capacity table this design chose deliberately (NOTES.md #6.2),
#       exhausted by a test that creates and frees in a loop;
#   (c) an entry point or constant MPI-3.0 *deleted*, which an MPI-5.0 ABI
#       header does not declare -- a build failure, and the right one;
#   (d) an *erroneous* argument the implementation would have diagnosed, which
#       conversion turns into a crash (NOTES.md #13.3);
#   (f) a difference measured but not yet attributed.
#
# There is no group (a) and no group (g) here. Both were about the older pin and
# the laptop respectively, and an empty group would be a line nobody maintains.

# --- (b) fixed-capacity tables, exhausted ----------------------------------

attr/fkeyvaltype 1 : 32 keyvals per iteration over 1024 datatype-pool objects is 32,768 in one process, against a 1024-slot table. MPIWRAPPER_KEYVAL_SLOTS is fixed and its entries are never reclaimed, because MPI-5.0 7.7 keeps a freed keyval usable by attributes not yet deleted, so no point is known-dead (NOTES.md #6.2). MPICH itself recycles the integer and has no such ceiling.

coll/nonblocking3 1 : one MPI_User_function trampoline slot per MPI_Op_create, never reclaimed (NOTES.md #6.2: the implementation may still be running the op after MPI_Op_free -- which is precisely what this test does). MPIWRAPPER_OP_SLOTS is 1024 static trampolines and this test creates several thousand ops; MPI_Op_create then answers MPI_ERR_INTERN, the test ignores the return value, and MPI_OP_NULL reaches MPI_Ireduce.
coll/nonblocking3 4 : the same, and at more than one rank the ranks that hit the exhausted pool abort while the rest wait, so the test times out rather than failing.
coll/nonblocking3 5 : the same.
coll/nonblocking3 10 : the same.

errhan/commcall 2 : 2000 MPI_Comm_create_errhandler calls against MPIWRAPPER_ERRHANDLER_SLOTS, which is 256 and is never reclaimed -- an errhandler is deallocated only after every object it was set on (MPI-5.0 9.4), which the wrapper cannot observe. Measured: 3490 of the test's 4000 handler invocations never reach the application's function.
rma/wincall 2 : the same table for windows: the test loops MPI_Win_create_errhandler and MPI_Win_set_errhandler 1000 times, and past 256 the wrapper has no slot, so MPI_ERRHANDLER_NULL reaches MPI_Win_set_errhandler.

# strict=FALSE); ci-scripts/suite/run-suite.sh does not pass it, because a
# line naming what the ABI omits is worth more than a skip.

datatype/simple_size_extent_oldapi 1 : uses MPI_Type_extent and MPI_Type_lb, deleted by MPI-3.0.
datatype/struct_no_real_types 1 : builds a struct type out of MPI_LB and MPI_UB alone, both deleted by MPI-3.0.
errhan/commcall_oldapi 2 : uses MPI_Errhandler_create/_set, deleted by MPI-3.0.
errors/datatype/type_extent_nullarg 1 : MPI_Type_extent, deleted by MPI-3.0.

# --- (d) an erroneous argument the implementation would have diagnosed -----
#
# Every one of these passes NULL where MPI requires a valid OUT pointer (or
# MPI_IN_PLACE where the standard forbids it) and expects MPI_ERR_ARG /
# MPI_ERR_BUFFER back. MPICH's error checking gives exactly that. Through this
# wrapper the implementation never sees the argument: the generated body hands
# it a local of its own and writes the converted result back through the
# caller's pointer, so the wrapper dereferences the null first and the process
# dies with SIGSEGV. The program is erroneous either way and MPI grants an
# implementation licence to do anything; what is lost is a diagnosis the
# wrapped implementation had. NOTES.md #3 records what closing this would
# cost, since it is a null check per written-through OUT parameter across 563
# generated bodies rather than a fix to any one of them.

errors/comm/comm_create_nullarg 1 : NULL for MPI_Comm_create's newcomm.
errors/comm/comm_create_group_nullarg 1 : NULL for MPI_Comm_create_group's newcomm.
errors/comm/comm_get_info_nullarg 1 : NULL for MPI_Comm_get_info's info_used.
errors/comm/comm_group_nullarg 1 : NULL for MPI_Comm_group's group.
errors/comm/comm_split_nullarg 1 : NULL for MPI_Comm_split's newcomm.
errors/comm/comm_split_type_nullarg 1 : NULL for MPI_Comm_split_type's newcomm.
errors/comm/intercomm_create_nullarg 1 : NULL for MPI_Intercomm_create's newintercomm.
errors/datatype/type_contiguous_nullarg 1 : NULL for MPI_Type_contiguous's newtype.
errors/datatype/type_vector_nullarg 1 : NULL for MPI_Type_vector's newtype.
errors/group/group_difference_nullarg 1 : NULL for MPI_Group_difference's newgroup.
errors/group/group_intersection_nullarg 1 : NULL for MPI_Group_intersection's newgroup.
errors/group/group_range_excl_nullarg 1 : NULL for MPI_Group_range_excl's newgroup.
errors/group/group_range_incl_nullarg 1 : NULL for MPI_Group_range_incl's newgroup.
errors/group/group_rank_nullarg 1 : NULL for MPI_Group_rank's rank.
errors/group/group_union_nullarg 1 : NULL for MPI_Group_union's newgroup.

NOTES.md #5.3 translates a sentinel only where it is legal for that parameter, so here the ABI's MPI_IN_PLACE reaches MPICH as an ordinary address and is dereferenced. Same shape as the nullargs above.



# --- (f) measured, not yet attributed --------------------------------------

errors/coll/noalias2 4 : four of the test's aliasing checks -- the rooted ones, MPI_Gather, MPI_Gatherv, MPI_Scatter and MPI_Scatterv with sendbuf == recvbuf -- return MPI_SUCCESS through the wrapper where MPICH answers MPI_ERR_BUFFER, while the six unrooted checks in the same test do fire. The same binary built with MPICH's own mpicc passes. Nothing in the wrapper touches either buffer pointer, so what differs is not yet known; the next step is to compare what MPICH's error-checking layer is handed in the two cases.
errors/coll/noalias3 4 : the same four checks, in the large-count (_c) forms.
