# Expected failures of MPICH's C test suite over this project in GitHub Actions,
# over **Open MPI 5.0.10 built from source, on both architectures**. Anything true
# of one architecture only belongs in xfail-ci-openmpi-<arch>.txt beside this file;
# check-tap.py reads the two as one and rejects a test listed in both.
#
# One line per test, `<dir>/<program> <np> : why`, in runtests' own naming.
# check-tap.py enforces it in both directions -- an unlisted failure fails the
# run, and so does a listed test that passed or that did not run -- and a line
# with no reason after the colon fails the run too.
#
# **Written from run 32182485327**, the first run in which an Open MPI leg got far
# enough to produce results: three of its four shards completed and the fourth did
# not (see "rma" below). Per shard, on aarch64: coll 192 tests / 8 failed, p2p 137
# / 20, rest 316 / 82. That run put 109 lines here, the failures both architectures
# produced, and four in the two delta files. **There are 110 now**, and one delta
# line: run 32302208489 failed threads/pt2pt/mt_iprobe_isendrecv 2 on both
# architectures over five attempts, so it moved here from the x86_64 file, which
# explains its own longer reason below.
#
# **`rma` is missing from this list, and it is no longer a gap: the directory is not
# run on the Open MPI legs.** It was a gap for a while -- both shards were killed six
# minutes in with "the runner has received a shutdown signal", on both architectures,
# twice each -- and teeing runtests into the job log localised it, first to
# `./rma/testlist.dtp [176 tests]` and then, once the monitor was added, to individual
# tests. The cause turned out to be upstream and not a triage problem.
#
# Open MPI 5.0 removed the `osc/pt2pt` one-sided component. `osc/rdma`, which replaces
# it, appears to build per-element state for a derived datatype where pt2pt packed and
# streamed it, so the cost tracks a datatype's *element count* rather than its byte
# count. `rma/transpose1` -- 3.8 MB of payload, `MPI_Put` onto a million discontiguous
# elements -- takes at least 14.6 GB and a 16 GB runner with it, where Open MPI 4.1.8
# completes the same test with the same wrapper in 1.7 GB. Neither `--mca btl self,sm`,
# nor a libfabric build with a real accelerated `btl/ofi`, nor excluding the offending
# test lines reaches it; the last only moves the death to the next casualty, because
# the casualties are chosen by datatype shape and no testlist line shows that.
#
# So `.github/workflows/ci.yaml`'s suite matrix excludes `rma` on these two legs, and
# there is nothing for this file to expect. `errors/rma/*` still runs, because the
# shards split on top-level directories, and its lines are below. Re-adding the shard
# is a two-line revert if an Open MPI release restores a streaming one-sided path.
#
# ci-scripts/suite/README.md has the rest, including the run ids for every
# measurement above.
#
# **Excluding rma does not by itself make these legs gate, and they stay
# report-only.** One thing is still outstanding and it is not rma: `openmpi /
# aarch64 / p2p` finished in ten minutes in one run and was killed after fifty in
# the next. Open MPI has a shard that hangs intermittently as well as the one that
# died reproducibly, and a green Open MPI leg needs that settled too.
#
# **A prediction this file used to carry was wrong and is corrected here.** It said
# the largest group would be decision 6's stubs answering
# MPI_ERR_UNSUPPORTED_OPERATION, on the grounds that 5.0.10 declares MPI_VERSION 3
# / MPI_SUBVERSION 1 and has no `_c` entry point. **Not one failure in this run was
# an unsupported-operation answer.** The version claim is still true -- group (a)
# is exactly that mismatch -- but this release provides the entry points the suite
# reaches, so the surface is there and what differs is behaviour.
#
# **Two of the groups deserve reading before the counts.** Group (d) is the
# erroneous-argument crash of NOTES.md #13.3, 22 tests of it. Group (f) is 66 lines
# that say what was observed and claim nothing more, which is the same honest state
# the older xfail-openmpi.txt was in -- but three families inside it are worth
# attention rather than acceptance, because they are wrong *data* rather than a
# difference in error reporting:
#
#   * `part/parrived*` and `part/pingping` -- partitioned communication delivering
#     zeros where the test wrote values, and a status count of 2 where 1 was
#     expected.
#   * `pt2pt/sendself` -- "expected (1,2) ... but found (0,1)", in about the
#     simplest operation the suite has.
#   * `coll/coll_large` -- "expect 0, got 255" on aarch64 and "got -1" on x86_64.
#
# The first two both report their mismatch one element off, which is a shape worth
# looking at as one bug rather than several. All of them pass over MPICH 5.0.1 on
# the same runners with the same wrapper build, so whatever they are, they are on
# the Open MPI side of the conversion. The method for settling any of it is S7's
# throughout: build the same test with Open MPI's own mpicc and see whether it
# still fails without the wrapper.
#
# Groups keep the letters xfail-ci-mpich.txt uses, so the two lists share a
# vocabulary; the kind matters more than the count.
